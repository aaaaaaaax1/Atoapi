# Atoapi v1.5.8

## 本版修复

- 修复工具传递诊断只观察顶层 `tools` 的问题，同时识别新版 Codex `input.additional_tools` 工具目录。
- 明确区分“顶层工具为空”和“请求没有任何工具目录”，避免把新版 Codex 的嵌套工具误报为工具丢失。
- 增加 `additional_tools` 从请求入口到冻结上游 wire 的隔离回归验证，确认代理不删除、不改写工具目录。
- 正式版只保留有界工具元数据诊断，不包含测试脚本、测试数据或完整请求内容。

## Codex 上下文设置

- 保持 Graphite 原界面，在 Codex 页“上游路由”右侧增加“上下文和自动压缩上限”入口。
- 支持独立填写 `model_context_window` 和 `model_auto_compact_token_limit`，单位为 Token；不预填示例值。
- 保存后的设置用于每次注入、重新应用和切换上游，也适用于模型直传模式，不要求指定模型。
- 两项均可单独留空。显式保存空值后移除对应覆盖，交由 Codex 默认处理，不会退回到隐藏的旧版上游阈值。
- 升级时尚未保存新设置的旧配置继续保留原行为；编辑器展示旧路由有效值并提示。关闭注入仍还原注入前的用户设置。
- 前后端校验正整数，并校验自动压缩上限不超过已填写的上下文窗口；保存不会启用已关闭的注入、重启代理或发起上游请求。

## 新版 Codex 兼容

- 停止写入已废弃的 `disable_response_storage`，重新注入时移除旧值，取消注入时也不会从旧还原记录重新引入。
- 不删除非 Atoapi 管理的 Guardian 或 MCP 配置。`guardianv2.thread_context` 的警告没有查到 Atoapi 写入来源。
- 保持官方模型目录和动态模型发现，不生成固定官方模型快照。
- 修复浏览器模拟预览误调用桌面窗口 API 导致白屏的问题，桌面行为不变。

## 工具转发排查

- 增加混合工具、命名空间工具、动态加载工具和浏览器续轮的回归测试。
- 诊断同时识别传统顶层 `tools` 和新版 Codex `input.additional_tools`，避免把嵌套工具误报为工具缺失。
- 回归验证覆盖 `additional_tools` 从客户端输入到冻结上游 wire 的原样保留。
- 增加真实 EXE + localhost 模拟上游的四轮验证脚本：浏览器调用、本地执行、自定义工具调用、携带工具结果完成；校验最终 `tools`、`tool_choice`、历史记录和单次转发。
- 旧版 1.5.6 的本地三轮验证未复现浏览器后丢失本地工具。该结果不能替代用户故障现场的逐请求清单；没有把未证实的历史故障宣称为已修复。
- 测试不执行真实 ADB、不操作手机，不消耗真实模型请求。

## 实际修复的工具兼容问题

- 修复 Responses 转 Chat / Anthropic 时命名空间内的自定义工具被遗漏的问题；声明、指定工具、历史调用及返回调用统一往返映射，保留 namespace、call_id 和自定义调用的 ctc_ 标识。
- 该转换分支不等于原生 Responses 直通分支；没有把它误认作历史 `No tool output found for custom tool call` 报错的确定根因。

## 工具传递诊断（可移除）

- v1.5.8 默认开启，在“设置 → 数据 → 工具传递诊断（临时）”可关闭。旧配置没有该字段时也默认开启；显式关闭后保持关闭。
- 仅本地记录请求入口、最终发送前、上游响应和下游发送边界的工具名称、类型、命名空间、tool_choice、调用配对标识及完整性状态，不保存聊天、参数、工具输出、描述、schema、密钥或原始错误文本。
- 同一请求使用本地 request_id 关联；最近调用优先，动态发现的工具名称单独记录。超限、丢弃或提前取消会明确标记，不能把“不完整”当作没有工具。
- 独立有界写入队列，不等待磁盘；tool-diagnostics.jsonl 与 tool-diagnostics.previous.jsonl 每个上限约 4 MiB，合计约 8 MiB。日志位于当前配置目录；页面显示实际路径。
- 不增加上游请求、探测、重试或 Token，仍有少量本地 CPU / 内存 / 磁盘开销。关闭后停止新日志，不自动删除已有诊断文件。
- 删除方式与证据判读见 TOOL-DIAGNOSTICS-v1.5.8.md，诊断模块不参与路由、执行或修复判断。
